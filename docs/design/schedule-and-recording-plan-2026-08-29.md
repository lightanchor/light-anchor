# 定时任务与过程记录 · 修正规划（2026-08-29）

首版实现（工作区未提交代码）在两处理解偏了，本文按修正后的语义重新规划。
待确认的问题集中在文末；确认前不动手。

## 语义修正

1. **记录不是人写的**。是软件对「用户做某件事的过程」的完整记录：点开始就开始记，
   放下/等待就暂停，恢复就继续，结束或切走就收尾归档；也可以脱离工作流**主动录制**
   一个过程。产物是过程的 trace（时间线事实），再由 AI 生成两种成稿：给人看的
   Markdown 分享文档，或给 AI 执行的 SKILL.md。这是扩展能力，默认不开，
   不改变现有任何流程。
2. **定时任务不要独立 tab**。到点除了提醒，还要**收集那一刻的现场**（检查点）；
   需要一个能筛选、能纵览的地方（时间线/日历），看到「这个点收了一份现场」，
   点进去能看当时的现场。

## 一、定时任务（修正）

### 语义

- 到点 = 系统通知 +（可选）**收集触发那一刻的现场**。
- 重复任务（每天/工作日/每周/每月）= 周期性现场检查点，如「每天 18:00 收一份现场」。
- 单次闹钟触发一次即完成。应用没开时错过的场次不补收（现场只有当下才收得到），
  重启后滚到下一场。

### 数据（在已实现基础上改造）

- `ScheduledTask` 保留：title/note/fireAt/repeatRule/status/日历事件来源。
  新增 `collectSceneOnFire: Bool`。
- **触发记录实体化**：新增 `ScheduledTaskFire { id, taskID, firedAt, sceneSnapshotID? }`
  与事件 `scheduledFireChanged`，替换首版的 `recentFireDates: [Date]` 数组——
  数组封顶会丢历史，而日历视图需要全量触发史；数组不封顶则单条事件越滚越大。
  每次触发一条事件，回放进 `scheduledFires: [UUID: ScheduledTaskFire]`。
- **触发时收集现场**：新增 `captureCheckpointScene()`——不依赖当前 episode，
  直接 `contextCapture` → `SceneSnapshotBuilder`（`targetID` 为空即可，模型本就可空）
  → `sceneSnapshotChanged` + `scheduledFireChanged` 同一次 commit。
  隐私走既有 `SceneCapturePreferences` 读取时过滤。
- 调度器、系统通知、EventKit 选时间、`PrivacyCapability.calendar` 权限行：沿用已实现。

### 界面（拆掉 tab）

- 移除侧栏「定时」目的地。
- **查看 + 管理**：回顾页新增「定时」区（位置待确认，见问题 2）：
  - 上半：即将到来的任务（新建/编辑/完成/删除，编辑表单沿用已实现的
    日期/重复/从日历选时间）。
  - 下半：触发历史——月历网格（每天标记触发/收集次数，风格对齐已有的
    `LightAnchorContributionGrid`）或按天分组的时间线；点某天展开该天的触发记录
    （时刻 + 任务名 + 有无现场）；有现场的记录点击打开当时现场，
    复用回顾页已有的 `selectedHistoryScene` 现场查看 sheet。
  - 筛选：按任务、只看有现场的。
- **创建入口**：回顾页该区内；可另加 现在页动作组（待确认）。

### 阶段 P1

fires 实体化 → 触发时收集现场 → 回顾页「定时」区（管理 + 日历/时间线 + 点开现场）
→ 拆 tab → 测试（触发产生 fire 事件与现场、回放、日历分组投影）。

## 二、过程记录（重做）

### 两种录制来源

1. **跟随工作**（可选，默认关）：episode 开始 → 录制开始；放下/进入等待 → 暂停；
   恢复 → 继续；结束或切换 → 收尾归档。一段 episode 对应一份记录。
2. **主动录制**：用户随时开始/停止，录一个跨目标的过程。

### trace 采样（事件驱动为主，周期兜底）

记录期间监听并差分：

- 前台应用/窗口切换（`NSWorkspace` 激活通知 + AX 窗口标题）→「切到 VS Code：xxx.swift」
- 文件/网页变化（windowFacts 的 documentURL/标题差分）
- 终端命令（terminalWorkingDirectory/当前命令差分；外部事件 completed/failed 的
  evidence 是最强信号，直接进 trace）
- 期间的捕获（想法/截图/链接）、等待开始与结果、episode 状态迁移
- 隐私：完全走 `SceneCapturePreferences` 排除规则，被排除的应用/域名/目录不进 trace；
  剪贴板与屏幕截图默认不进（待确认）
- 条目 `{ at, kind, title, detail, address }`；相邻重复合并；单份上限
  （如 800 条，超限保头尾、丢中间并标注「省略 N 条」）

### 存储

- **trace 不进事件日志**：`commit` 是整文件原子重写，长 trace 会放大每次写入。
  每份录制一个文件 `recordings/<uuid>.json`（`LightAnchorStorage.recordingsURL()`；
  `LocalDataErasure` 与备份/恢复清单同步登记）。录制中先在内存缓冲，周期落盘。
- 事件日志只存 `RecordingSession` 元数据（id、关联 target/episode、起止、状态、
  条目数、标题）＋生成的**成稿 markdown**（成稿小，进日志才能回放、检索、备份）。
- 首版 `RecordNote` 改造为成稿载体：AI 管线（`composeRecordMarkdown`、两种风格
  提示词、三引擎实现）、导出/复制（`<slug>.md` / `SKILL.md`）全部复用，
  输入从「手写草稿」换成「trace 事实行」。

### 生成

- trace → 按时间排列的事实行；提示词约束「只依据事实行，不虚构命令与路径」。
- 给人看的：过程复盘（背景、按序步骤、结果）；skill：从过程提炼可复用操作
  （frontmatter name/description + 适用场景 + 执行步骤 + 验证），拿不准的步骤标「需确认」。
- 长 trace v1 直接截断喂入；v2 再做分段摘要。

### 界面

- 记录列表 + 详情（trace 时间线、生成两种成稿、导出/复制、删除）；
  入口位置待确认（问题 3）。
- 当前工作卡：**录制状态必须可见**（在录指示 + 一键停止）；主动录制的开始按钮。
- 设置：「跟随工作自动录制」全局开关（默认关）。

### 阶段

- P2：主动录制（采样器 + trace 落盘 + 列表/详情 + 生成/导出）。
- P3：跟随 episode 的自动录制（含暂停/恢复）+ 筛选与打磨。
