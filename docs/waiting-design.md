# 等待的定稿（2026-09-05）

**等待不是一个你要去看的地方，是一个到期会来找你的东西。它替你数的不是「等到了没有」，是「还剩几天」。**

---

## 为什么要改

现在「暂时放下」和「交给等待」，落地几乎是同一件事：都停表、都存现场、都能一键回去、都在清单里等你回头找。用户学了两遍，得到一样的东西。

而且承诺没兑现。宣传写的是「等回信、等确认的事交给它，到点来找你」，实际上它不会来找你——你得自己回轻锚点一下「结果到了」。可你会知道结果到了，只可能是因为你已经在邮箱里看见了。看见了还要回来销一次账，这是**多记一件事**，不是少记一件事。

还有一处更别扭：选了「定时提醒」的等待，到点会推一条通知说「你在等的一个结果到了」。什么都没到，只是闹钟响了。

## 两条轴，不能压成一条

一件放在那儿的事，身上有两个互不相干的属性：

|  | 球在谁手里 | 有没有截止日期 |
|---|---|---|
| 周报周五交 | **你** | **有** |
| 重构那个模块 | 你 | 没有 |
| 等客户签合同（下周一开工要用） | 别人 | **有** |
| 等财务报销 | 别人 | 没有 |

四个格子都住着人。**截止日期不是等待的私产**——你自己的事一样会有硬期限，而那格恰恰最容易出事。

两条轴各管各的：

> **截止日期回答「什么时候」。球在谁手里回答「到时候干什么」。**

## 三条地基

**一、等待和放下的唯一区别是：下一步在谁手里。**
放下——球在你手里，什么时候回去你说了算。等待——球在别人手里，你回去也没用。这个区别值钱，因为清单上最烦人的事就是：一件卡在别人那儿的事和一件你自己拖着的事长得一模一样，你每扫一行都得重想一遍「这条今天能动吗」。

**二、软件永远判断不了「结果到了」，但能百分百判断「快到期了」。**
前者要它看见外面的世界（邮箱、群、对方公司的流程），后者只要一块表。所以整个设计压在后者身上。

**三、只有你亲口押了截止日期的事，才有资格打断你。**
这条对所有事情通用，不分你的还是别人的。

---

## 改成什么样

### 1. 等待不再是一个独立页面

并进稍后，只留一张清单，按**球在谁手里**分两组——判据只有这一条，跟日期无关：

```
可以动
  周报　　　　　　　　　　还有 2 天
  重构解析器　　　　　　　放下 6 天
  面试记录整理　　　　　　放下 2 天

等着别人的 3 件 · 最近的周五到期　▸
```

**可以动** —— 球在你手里。刚解冻的排最上面，标一句「结果到了 · 2 小时前」。

**等着别人** —— 默认折叠成一行。你每天扫清单是为了挑一件事做，这几条今天挑不了，就不该占视线；但折起来那行的尾巴要报最近的一个期限，这样即使收着，你也知道里面有没有火。

组内排序：押了日期的按日期往上排，没押的往下沉。

顶层导航从「现在 / 稍后 / 等待 / 环境 / 回顾」变成「现在 / 稍后 / 环境 / 回顾」。

### 2. 截止日期是每件事都能押的，而且可以留空

**押的是日期，不是时长。** 不问「多久算太久」——「三天」是你对别人耐心的估计，是编的；编出来的数字响起来没分量，响三次你就学会无视它。「周五」是你自己日程上的硬点，你知道它，不用编。**一个是关于别人的猜测，一个是关于自己的事实，只有后者配打断你。**

日期还能倒着算。「周五要用，今天周三，催一趟要一天」——这句话自己就把动作算出来了。时长模型里没有终点，没有任何东西可以往回倒。

**允许留空**，因为确实有一类事没有期限——「重构那个模块」「等财务把报销打过来」，你不需要它在哪天之前完成，只是不想让它无声无息消失。硬逼人填，人就会随便填一个，又变回编数字。填不填，把每件事分成两种：

|  | 押了日期 | 没押日期 |
|---|---|---|
| 是什么 | 一个有后果的承诺 | 一笔账 |
| 清单上的数字 | **还有 2 天** → **就是今天** → **过期 1 天** | 放下 6 天 / 已等 23 天 |
| 会不会来找你 | 会，在还来得及的时候 | 永不打扰 |

问法随归属换一句话，别的都一样：

- 你的事：**什么时候必须做完？**
- 别人的事：**什么时候必须拿到？**

### 3. 清单上的数字要掉头

现在这个软件里所有数字都在往上加——放下 3 天、已等 5 天、专注 47 分钟。往上加的数字天生是死的，它只在描述过去。

押了日期的要**倒着走**：还有 2 天 → 就是今天 → 过期 1 天。倒着走的数字自己会喊人，扫一眼清单，哪条在逼你，不用读字就看得出来。

没押日期的仍然往上加，因为它本来就该是惰性的。

### 4. 到期来找你：还来得及的时候，两套话

到期那天才响已经晚了——不管是做还是催，都要时间。**默认提前一天**，话里必须有**日期**和**后果**。

**你的事**：
> 「周报」周五要交，你已经放下 6 天了。今天得动了。
> **现在就做 · 改到〔　〕· 算了**

**别人的事**：
> 「客户确认合同」周五要用，还没回信。今天不催就赶不上了。
> **去催 · 改到〔　〕· 不等了**

骨架一样：**推进 / 改期 / 放手**。中间那个通用，两头各说各的话。

「现在就做」是这里最值钱的一颗：点下去不是跳到一个详情页，是**把你上次写到一半那个现场原样铺开**——文档开在那一段，浏览器还是那几个标签，表接着上次走。待办软件到期只能提醒你「有这么回事」，剩下的重新想；只有轻锚记得你停在哪。**这才是它有资格管期限的理由。**

不弹窗、不抢前台，这条不变。

### 5. 「结果到了」是你存进去的，不是软件测出来的

不再有「结果到了」这一组——那只是「可以动」里刚解冻的一条，不值得单开一个房间。

关键是**存进去的那一下要够便宜**。结果到达的那一刻，你人在邮箱里，不在轻锚里。要求你切过来、翻到等待、找到那行、点一下，这比直接把事处理掉还麻烦，没人会干。

所以入口放在你人所在的地方：⌥⌘N 那个随手记的小窗，顶上加一行——

> 这是我在等的：〔客户确认合同〕〔法务回复〕〔CI 跑完〕

瞄一眼点一下，窗关掉，光标回到邮件里。顺手把那封邮件的链接或截图存成「结果是什么」的凭据。你本来就要记一笔，顺手就把账销了。

### 6. 护栏：怎么才不变成第 N 个待办清单

给事情加日期，最大的风险就是滑成待办软件，而 README 第一句就是「没有第 N 个待办清单」。线画在这里：

- **轻锚永远不问你期限。** 它是一个可以留空的格子，不是必填步骤，不做新手引导教你「给任务设置截止日期」。
- **不做优先级、不做重要紧急四象限、不做手动排序。** 顺序只由两件事决定：能不能动，日期近不近。这两件都是事实，不需要你评估。
- **不累积愧疚。** 没有「逾期 7 件」这种红色徽章。**一件事到期只说一次，给三个动作，说完就过去了。** 你选了「算了」，它就真的算了，不会隔天又冒出来。

待办软件让人烦，不是因为它有日期，是因为它把清单本身变成了一件要你伺候的事。轻锚的清单只是你被打断之后的副产物，唯一任务是把你送回去干活。有日期不改变这一点，**开始要求你打理它**才会。

---

## 要删掉的

- 「等待」这个独立页面和它的导航项
- 「结果到了」这个分组（降为「可以动」里的一个标记）
- 定时提醒到点自动宣布「结果到了」——软件不知道结果到没到，不许它这么说
- 「下次切换时提醒」这个选项（本来就没有界面入口）
- 「等待中」作为一种工作状态——等结果的事就是被放下了，它身上只是多挂了一件没到的东西

## 要保留的

- 一件事可以同时等好几个结果
- 开始等待时自动存现场；回去时一键重返，表接着走
- 结果的凭据（那封邮件、那张截图）留在记录里，回顾时看得见
- 一件事结束或放弃时，它身上没解决的等待一起收掉，不留孤儿

---

## 验收（拿这六条对）

1. 早上打开轻锚，一眼看出今天能挑哪几件，**不用逐行去想「这条能动吗」**
2. 一件你自己的事也能押期限，到期时它把你**放回上次的现场**，不是给你一条干巴巴的提醒
3. 押了日期的等待，在还来得及的那天来找你，话里有日期和后果，不是「已等 N 天」
4. 没押日期的事，永不弹、永不响、不占视线，但翻到它时看得见放下/已等多久
5. 在邮箱里看见回信，⌥⌘N，两下之内销账，光标回原处
6. **任何时候软件都不会说「结果到了」，除非是你自己说的**

## 动手顺序

**四步已全部落地（2026-09-05）。**

1. ~~**清单合并**~~ —— 等待并进稍后、按归属分两组、第二组默认折起，导航从六格变五格。没动数据。
2. ~~**押日期**~~ —— 每件事都能押，可留空；清单上的数字掉头倒计时。
3. ~~**到期来找你**~~ —— 提前一天，两套话，三个动作（推进 / 改期 / 放手）。
4. ~~**随手记小窗的销账入口**~~ —— 顶上那一行「这是我在等的」，带凭据。

### 第一步 · 清单合并

分组口径收进一份投影 `LaterListProjection`（`Services/LaterListKit.swift`），稍后页、
侧栏计数、空页面那两枚胶囊都从它取数——换一件事面板里那段「绕开 episode.state」的
特判，从此是唯一口径而不是特例。顺带删掉的死物：等待页与它自己的「添加一个等待」
入口（同一动作的第二个入口）、侧栏那枚暖黄徽章、`LightAnchorGroupHead`、
`LightAnchorReadoutCount` 的多段初始化器、`waitingProgress` 里两条打不到的分支。

折叠组返工过一次：第一版收着是一块岛、摊开变成「光秃秃的标题 + 另一块岛」——
点一下，你点的那个东西自己换了形状；而且整行 55% 透明把「已经有结果」「不再等待」
两颗按钮也洗淡成了看起来点不了。现在是同一块岛往下长，行不做 frost。

### 第二步 · 押日期

期限挂在**事情**和**等待**两边（`dueAt` + `nudgedAt`），都可留空。倒计时按日历天算
（`Domain/DueDate.swift`）——人说的「还有两天」是两个日历天，不是 48 小时。

三处和定稿的偏差，都是实现时想清楚的：

- **`overdue` 不作为一种状态存，而是从 `dueAt` 推出来。** 存下来就要在每次启动、
  每次改期时对账，而且改了日期它就成了谎；推出来永远是对的。
- **「等待中」这个工作状态整个删掉**（旧日志里的 `"waiting"` 解码成 `paused`）。
  交出去的那一刻这件事就离开「现在」页——你在等的时候一定在做别的，把它按在
  那一页上，那一页就成了一件你并没有在做的事。
- **旧的「定时提醒」时刻迁成期限**（`WaitingItem` 自定义解码读旧的 `monitor.date`），
  别让用户已经填过的日期凭空消失。

### 第三步 · 到期来找你

`WaitingCoordinator` 从「睡到点、宣布结果到了」改成「睡到窗口、催你一次」。
它以前推的那条「你在等的一个结果到了」是句谎——什么都没到，只是闹钟响了。

到期条（`DueNudgeBand`）压在**现在页和稍后页**顶上，两套话两套动作。
「去催」不碰等待的状态，只把当初交出去时的现场铺开（那封邮件、那个群）——
待办软件到期只能说「有这么回事」，只有轻锚记得你停在哪。

### 第四步 · 随手记里销账

⌥⌘N 小窗顶上一行「这是我在等的：〔…〕」，最多三条（押了期限的排前面）。
点一下即确认结果已到，手上那点草稿存成凭据，窗关掉，光标回原处。

### 返工一轮（同日）

**「开始一件事」独立成一张便笺。** 它原先借用「换一件事」那个面板，而那是个
**选择器**——左栏清单、右边写着「回去开 N 样」的邮票、交接确认。凭空立一件事时
清单是空的、邮票是空的，用选择器的壳装一次声明，看着就别扭。而且那条路只收一个
名字：期限、开工环境全问不了（真正的 `StartWorkView` 当时根本打不开，
`showingStartWork` 从来没被置过 true）。

现在它是一张 520 宽的便笺，三行：**叫什么**（唯一必填，焦点在这儿，回车就开始）、
**什么时候要做完**、**开工要开什么**。后两行都用「空状态自己说话」的字段，
不再是开关加字段两步——**用户不定，就默认没有。** 期限摆在台面上而不是藏进「更多」：
它是这个软件唯一能替你盯住的东西，藏起来就等于没有。备注这类才进「更多」。

面板里那行「新开…」不自己建目标了，把名字交给这张便笺——一条创建路径，
一个地方知道怎么把一件事立完整。

**期限那一格只挑日子。** 「周五 23:51」里那个 23:51 是实现细节（期限落在那天末尾），
显示成「周五」。面板里多一颗「撤掉期限」。

**折叠组头行不再变高。** 展开时它原来会多长一句解释——你点一下，你点的那一行
自己长高了，手感像跳了一下。那句话删掉，组名和每行的「已等 X」已经说清了。

### 又返工一轮：这些界面得长得像这个 app

第一版新界面是照**设置对话框**的路数堆的，和这个 app 的样子不是一个物种：

- 「开始一件事」有头部图标 + 眉题 + 标题 + 副标题四行铺垫，然后左标签右控件的表单行，
  再一个孤零零的「更多」三角。可这个 app 里根本没有这种东西——它自己早有一套
  「打一行字就走」的样子，就是 ⌥⌘N 那个窗：**没有头部，光标直接落在卡面上，
  底下一排安静的 chip，右边算了 + 一颗蓝箭头**。开始一件事跟它是同一种交互。
  现在照那个骨架重做，期限就是底栏上的一颗 chip（「不着急」）。
- 到期条里那个带边框、带图标、带 chevron 的日期盒子，一行一个，重得压过了句子本身。
  换成同款 chip；「不等了」降成纯文字键。三个动作这才有轻重：蓝色主键 → 安静 chip →
  文字键。
- 倒计时原来是一颗暖黄药丸。这套语言里语义色落在**点**和**字**上，
  一行挂一颗带底色的标签，整张清单就花了。现在它只是副题里的一段字：
  远着灰、近了暖黄、过了转红。

## 落地备忘

*（这一段是写给实现的，不影响上面的设计。）*

- 「等待中」目前是一段工作的状态之一，和「放下」并列。这个建模是错的：你一旦真的去干别的，它自己就会漂移成「放下」，而没到的那件事还挂着——切换面板里已经有一段特判在绕开它。改成「等待只是挂在一段工作上的标记」之后，那段特判就变成唯一的取数口径，不再是特例。
- 日期挂在「事情」上，不挂在等待上——一件事可以既有自己的完成期限，又在等别人的东西。两个日期，各归各位。
- 「多久算太久」那套时长逻辑从来没做过，直接跳过，按日期实现。
- 到点的定时器不再宣布「结果到了」，改成把这条标成「过期」；「结果到了」只能由人确认。
- 提醒策略那三档（手动 / 到点通知 / 下次切换时）整个去掉：响不响由有没有押日期决定，不需要第二个开关。
- 「定时」跟这次改动碰不到：定时任务身上没有任何指向事情的字段，它管的是时刻，不管事情。这次不动它。
- 文案两套语言表都要动；「等待」相关的键会有增删。
