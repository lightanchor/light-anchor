# 「对话」页记忆与检索设计（重新思考版,2026-08-25）

前情:对话工程(流式/真多轮/可取消)已完成。外接一套现成记忆服务的路子评估过,
体积与依赖代价不划算,不走。本文是给这个 app 量身的方案——**零新增运行时依赖,
每一块都是系统能力或既有代码**。

## 设计原则(与 app 现有价值观对齐)

1. **事件日志是唯一事实源**——索引、摘要都是可重建的缓存,坏了删了都不心疼;
   数据抹除时一并清掉。
2. **依据可核对**——记忆不是黑盒向量,回答的每一行依据都能点开看来源;
   长期记忆是一份用户能打开、能改、能删的文本文件。
3. **有错误就显示错误**——蒸馏引擎不可用就跳过并记诊断,不冒名降级。
4. **轻**——不带 Node、不带模型文件、不加第三方库。

## 三种记忆,各答各的问题

| 记忆 | 回答什么 | 实现 | 状态 |
|---|---|---|---|
| 结构化聚合 | "上周专注多久""在等什么" | MemoryRecall 现有的账本/目标纵深/等待/今天层 | 已有 |
| 可检索档案 | "蓝点重构记过什么想法""找那条链接" | **MemoryIndexKit**:SQLite FTS5 + 端侧向量 | **已建(2026-08-25)** |
| 精编长期记忆 | "我做决定的偏好""那个项目的脉络" | **记忆笔记文件(新)**:整体注入 + 周期蒸馏 | 待建·二期 |

一期落地记录:MemoryIndexKit(索引 actor + 派生 + RRF 混合检索)、追问改写
(引擎按需、6 秒限时、失败用原句)、聊天回合入索引(增量 + 存档回填)、
「删除全部本地数据」联动清索引;验收测试见 MemoryIndexTests
(含零字面重叠的语义命中、真实端侧向量中文冒烟)。

### 一期 · MemoryIndexKit(可检索档案)

- **存储**:数据根下一个独立 SQLite 文件(系统 libsqlite3,无第三方库)。
  FTS5 用 **trigram 分词器**——中文不需要分词器就能索引子串,直接取代
  MemoryRecallKit 里 O(n²) 的连续子串暴力匹配(那套下线)。
- **语义重排**:`NLContextualEmbedding`(系统自带端侧多语言句向量,资产由
  macOS 按需下载)。语料量级只有几千条,向量存 blob、暴力余弦即可,不需要
  向量库。**中文效果先实测**;资产未就绪或效果不佳时纯 FTS5 也远好于现状。
- **入索引的内容**:捕获(含 OCR 文本)、工作痕迹摘要、今天层、聊天问答回合。
  事件提交后增量更新;索引版本号 + 全量重建入口。
- **检索融合**:FTS 候选 ∪ 向量 top-k → 时近与类型加权(权重复用 SearchKit)
  → 进事实列表,标签沿用「捕获/工作」等来源,依据面板每行可溯源。
- **追问改写**:检索前用近几轮对话把问题补全("那件事呢"→具体指代),
  一次廉价模型调用;引擎不可用则跳过,用原句检索。

### 二期 · 精编长期记忆(记忆笔记文件)

思路:**一份小而精编的记忆文件 + 整体注入,不走检索**。几 KB 的东西
每次全量给模型,比检索片段更连贯,也省掉一整套召回调参。四条要点:
蒸馏时把文件现状嵌进提示词,让模型编辑现实而不是凭陈旧记忆重写;
审计用机器 diff 而不是模型自述的改动摘要;LLM 失败绝不丢数据;
文件是用户可见的纯文本,能打开、能改、能删。

- 数据根下 `memory-notes.md`,用户可直接打开编辑;每次提问整体注入(几 KB)。
- 蒸馏:聊天回合与工作痕迹积累到阈值后,批量(带游标防重)交给现有引擎座
  精编该文件;macOS 26 端侧模型可用后免费跑。引擎不可用→跳过 + 诊断。
- 变更审计:记一条事件/诊断(改动摘要来自真实 diff)。

### 引擎层(不动)

云端 BYOK 十二家预设 / Apple 端侧 / 启发式离线,照旧。

## 验收标准(一期)

- "蓝点重构记过什么想法"换措辞(如"侧栏动画那个主意")也能命中;
- "那件事呢"式追问能接上上一轮的指代;
- 依据面板每行都能对回一条真实记录;
- 索引删掉后自动重建,回答不变;数据抹除后索引同步消失。

API Key 迁 Keychain(现明文在 UserDefaults,且会进备份 tarball);
英文时间词解析与提示词双语。
